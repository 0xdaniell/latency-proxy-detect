Latency-based proxy check

Are you behind a VPN or a proxy?

This page times the path to your browser and the path to your IP address. If the browser is much farther away than the address, something sits in between.

Ready
Starting the measurement takes about ten seconds.

What was measured

Browser (WebSocket echo)
–

Application layer: answered by your browser, wherever it runs.

TCP handshake
–

Transport layer: answered by whatever opened the TCP connection.

Ping (ICMP)
–

Network layer: answered by the IP address you connect from.

0trace
–

Network layer: a traceroute inside this connection.

Difference used: – (threshold 50 ms, rule –)

How it works

  1. Your browser opens a WebSocket to the server, which sends it 100 small pings. Each carries a random nonce, so the reply can't be sent early.
  2. The server reads the round trip time of the TCP handshake, pings your IP address, and runs 0trace: a traceroute sent inside the already-open connection, which passes firewalls and NAT.
  3. With a VPN, the pings to your IP stop at the VPN server, but the WebSocket travels on to your browser. A difference above 50 ms means the browser is far from the address it connects from.

Limits. A VPN server within roughly 1,000 km of you is usually not detected. Neither is a browser that itself runs on a remote machine. This is one signal, not proof.

Method: Ramesh, Winter, Korman, Ensafi. CalcuLatency: Leveraging Cross-Layer Network Latency Measurements to Detect Proxy-Enabled Abuse. USENIX Security 2024. This site is an independent implementation.

Privacy. The server keeps a log of each measurement: the IP address you connect from, the timings above, the result and your browser's user agent. It sets no cookies and runs no third-party scripts. To check whether the last hop shares a network with your address, the server may look the address up on RIPEstat.
